## 3. Дизайн-система (Light Business / Unslop)

В проекте действуют универсальные проектные скиллы из каталога `.agents/skills/`:
- **`.agents/skills/landing-page-design/`** — принципы B2B-конверсий, сетка 4px, вложенные скругления.
- **`.agents/skills/unslop/`** (автор Дамир Соколовский, [@heydamir](https://github.com/heydamir/unslop)) — 9 проходов очистки интерфейса от «нейрослопа».
- **`.agents/skills/brainstorming/`** — исследование требований перед реализацией.

### Строгие правила оформления:
- **Стиль:** Чистый, строгий, светлый корпоративный стиль (Unslop). Чистый белый фон (`#FFFFFF`), снежный фон секций (`#F8FAFC`), акцент небесно-голубой (`#0284C7` / `#0EA5E9`), границы `border-slate-200`.
- **Типографика:** Шрифт **Manrope** (или **Geist**). Контрастный текст `slate-900` (`#0F172A`).
- **Запреты по тексту и графике:**
  - Никаких эмодзи в интерфейсе и текстах.
  - Никаких длинных тире `—` (использовать только короткие дефисы `-` с пробелами).
  - Никакого курсива в интерфейсе.
  - Никаких абстрактных клише («революционный», «инновационный», «next level», «10x»).
  - Никаких радужных/фиолетовых градиентов, летающих 3D-сфер и неоновых проводов.
- **Скругления (Nested Radius):** $\text{внутренний радиус} = \text{внешний радиус} - \text{отступ}$.

## 4. Стек проекта и команды

- **Стек:** React 18 + Vite 5 + Tailwind CSS + Lucide Icons.
- **Запуск локально:** `npm run dev`
- **Проверка сборки:** `npm run build`
- **Деплой:** Автоматический CI/CD на GitHub Actions при пуше в ветку `main`.

## 5. Регламент SDLC и жизненный цикл задач (`docs/tasks/`)

Все задачи ведутся строго в папке `docs/tasks/<XXX_название>/` с инкрементом номера (`015_...`, `016_...`).

### Обязательная структура папки задачи:
1. `REQUIREMENTS.md` — бизнес-требования, боли, ожидаемый исход для бизнеса, критерии приемки.
2. `SPECIFICATION.md` — архитектурное и техническое проектирование (компоненты, API, стили).
3. `IMPLEMENTATION_PLAN.md` — пошаговый чек-лист выполнения со статусами `[x]`, датой и результатом.

### Цикл трех тактов:
1. **Такт 1 (Диалог):** Обсуждение гипотез и ограничений. Код не пишется.
2. **Такт 2 (Спецификация):** Формирование требований и чек-листа шагов в `docs/tasks/`.
3. **Такт 3 (Реализация):** Правка компонентов строго по плану.

### Процедура Clock-Check (перед закрытием задачи):
1. Обязательный запуск `npm run build` (код завершения 0).
2. Проверка отсутствия сломанных ссылок и консольных ошибок.
3. Отметка шагов в `IMPLEMENTATION_PLAN.md` со статусом `Completed & Verified`.
4. Git-коммит с привязкой к задаче: `feat(task-XXX): ...` или `docs(task-XXX): ...`.
